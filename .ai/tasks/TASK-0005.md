## 1. Objective

Start M2 by making the frontend's Real API mode truthful and failure-safe.

Today the frontend can switch to `createRealRepository()`, but connection failure can leave previously loaded Mock data visible, while the sidebar still hardcodes “系统状态 正常 / AI Engine 在线”. This can make a disconnected Real mode look successfully connected.

Fix that boundary before visual polish.

## 2. Current State

- M1 real visual source → model → fact runtime path is complete.
- Frontend already has Mock/Real repository abstraction.
- `createRealRepository()` maps plugins/events/review/analysis/objects/persons to AI REST API.
- `npm run smoke:real` already checks core AI endpoints.
- App mode switch loads events/plugins/objects/persons with `Promise.all`.
- On a Real API fetch failure, a toast appears but old in-memory data may remain.
- Sidebar health card currently renders static “系统状态 正常”, “AI Engine 在线”, and “媒体流 Mock”.

## 3. Exact Requirements

1. Introduce an explicit frontend AI data-source connection state such as:
   - loading
   - online
   - offline/error
   - Mock/local where appropriate.
2. When switching data sources, do not retain stale data from the previous mode while the new source is loading or failed.
3. In Real API mode:
   - successful initial load marks AI Engine online;
   - failed initial load marks it offline/error with a concise reason;
   - no Mock events/plugins/objects/persons may remain displayed as if they came from Real API.
4. Sidebar/system status must derive from actual mode/connection state rather than hardcoded “正常/在线”.
5. Media status must remain truthful:
   - Mock may say Mock;
   - Real mode must not claim a live stream unless Makerverse/media adapter actually resolves one.
6. Actions that require Real API (analysis, review, plugin toggle, registry create) must surface a clear failure and must not silently fall back to Mock.
7. Preserve Mock demo behavior and visual structure.
8. Preserve the existing Repository abstraction; do not scatter direct fetch calls across page components.
9. If useful, add a small `health()` or equivalent repository method, but avoid broad API redesign.
10. Update frontend README/docs to explain Real connection semantics and failure behavior.

## 4. Verification

Required:
- `npm run build`

Use deterministic checks where practical. Do not introduce a large new frontend test framework solely for this task.
