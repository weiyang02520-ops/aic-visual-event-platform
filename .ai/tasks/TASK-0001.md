## 1. Objective

Add one optional, real-model visual provider path for local video/frame input that can produce normalized person detections and explicit pose keypoints (at minimum nose, left_wrist, right_wrist) for the existing AI pipeline, without rewriting the existing relation engine, temporal reasoners, plugins, event schema, storage, frontend, Makerverse, or livestream-rs.

This task is provider integration, not model training. It should replace the current “fixture supplies keypoints” boundary with a real provider adapter when the optional dependency/model is available.

## 2. Why This Task Now

The repository already has frame sources, detector/tracker contracts, relation facts, keypoint action extraction, elderly/workshop temporal reasoning, plugins, SQLite, API, privacy guards and 363 passing tests. The explicit remaining gap is real pose/object model inference.

3. Person observations must be able to carry bbox, confidence and keypoints `nose`, `left_wrist`, `right_wrist`, with source/timestamp provenance through the existing path.
4. Availability must be explicit: missing dependency/model → unavailable with reason; malformed output → fail closed.
5. Do not commit model weights.
6. Add deterministic adapter tests with fake/stub model results; CI must not require network/GPU.
7. Add an integration-style test proving a local frame can reach the existing normalized observation/fact path through the adapter.
8. If environment permits optional package + official lightweight model, perform one non-blocking real smoke test and record exact evidence. If not, explicitly mark real runtime unverified; adapter tests can still PASS.
9. Update provider/algorithm documentation and truthfulness boundary.
10. Keep existing Mock/fixture/CPU behavior working.
