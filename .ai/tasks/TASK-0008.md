## 1. Objective

Generalize the current skeleton action logic into a reusable AI-layer action-primitive stage.

Today `KeypointActionExtractor` is tightly shaped around the medication path: it only emits `hand_to_face` when a medication relation is already present. The final competition algorithm should instead produce generic, scene-independent skeleton/object action facts that scene reasoners can compose later.

This task must preserve current medication behavior while removing medication-specific coupling from the low-level skeleton/action layer.

No frontend work belongs in this task.

## 2. Current State

- Canonical COCO17 `SkeletonObservation` is complete.
- Generic object-location `VisualMemory` is complete.
- `RelationEngine` already emits generic:
  - `near`
  - `pickup_candidate`
  - `putdown_candidate`
  - `motion`

  - consumes canonical skeletons;
  - uses nose + wrists;
  - requires medication-object relation facts;
  - only emits medication-linked `hand_to_face`.
- Existing medication temporal reasoning depends on a matching `hand_to_face` fact.
- Full AI baseline after TASK-0007: 389 passed / VERIFY_OK.

## 3. Requirements

### 3.1 Introduce a scene-independent action primitive layer

Refactor or replace `KeypointActionExtractor` with a generic skeleton/object action extractor while preserving a compatibility path for existing callers if needed.

The extractor must not call medication label helpers to decide whether an action primitive exists.

It should operate on:
- current-frame person skeleton observations;
- current-frame non-person object observations;
- generic relation facts;
- frame index/source/timestamp/continuity provenance.

### 3.2 Add `hand_near_object`

Emit a generic `hand_near_object` PrimitiveFact when a valid left/right wrist is sufficiently close to a non-person object's bbox.

The fact must include:
- person identity/label;
- object identity/label;
- which wrist;
- wrist-to-object distance;
- threshold/reference used;
- confidence;
- source_id;
- continuity_segment;
- timestamp.

Requirements:
- any non-person object may qualify; do not restrict to medication;
- a person must never be treated as the object;
- invalid/missing/low-confidence wrist points do not produce the fact;
- multiple same-label objects remain distinct by track/entity identity;
- do not pair observations from another source/frame/continuity segment.

### 3.3 Generalize `hand_to_face`

`hand_to_face` must become a generic skeleton action primitive based on wrist-to-face geometry, not on medication classification.

It must:
- be derivable from person skeleton geometry alone;
- identify wrist + face reference;
- preserve source/time/continuity/person provenance;
- keep current debounce/dropout behavior or an equivalent well-tested episode policy.

When an object is simultaneously associated with the same wrist via `hand_near_object`, the action may carry/link that object as interaction context. If several objects qualify, selection must be deterministic and conservative.

Do not fabricate an object association when none is supported.

### 3.4 Preserve conservative pickup/putdown semantics

Current `pickup_candidate` / `putdown_candidate` relation facts are allowed to remain relation-layer primitives.

Do not rename them to definitive `object_picked` / `object_put_down` unless new evidence actually proves the stronger claim.

If useful, add an explicit metadata field such as `evidence_level: "candidate"` or document the semantics.

Do not introduce a definitive `carried` claim solely from hand proximity.

### 3.5 Medication compatibility

Update the medication path so existing `MedicationSequenceReasoner` still receives a medication-associated `hand_to_face` fact only when:
- a generic `hand_to_face` action occurred;
- a medication object is validly associated with the relevant hand/object interaction in the same source/frame/continuity context.

This scene-specific association may happen in a small adapter/association step, but the low-level skeleton action extractor itself must remain scene-independent.

Existing complete/incomplete medication sequence tests must stay green.

### 3.6 Provenance and privacy

All emitted action primitives must preserve:
- source_id;
- timezone-aware timestamp;
- continuity_segment;
- person/object track identity where applicable;
- confidence and explainable geometry.

No raw image/gray/RGB/BGR/pixel data may enter action facts.

### 3.7 Deterministic tests

At minimum prove:
1. person wrist near an arbitrary non-medication box emits `hand_near_object`;
2. wrist far from object does not emit it;
3. low-confidence/missing wrist does not emit it;
4. person-only skeleton can emit generic `hand_to_face` without medication;
5. multiple objects are associated deterministically by geometry/identity, not label merging;
6. cross-source facts/observations cannot pair;
7. mixed-frame timestamps cannot pair;
8. continuity boundaries do not reuse an old action episode;
9. medication sequence behavior remains compatible and reviewable;
10. no raw pixels enter action facts;
11. FrameFactExtractor integration emits the generic primitives in the normal pipeline.

## 4. Documentation

Update algorithm documentation to make the layers explicit:

```text
Skeleton / Object observations
  -> spatial relation facts
  -> generic action primitives
       - hand_near_object
       - hand_to_face
       - pickup_candidate
       - putdown_candidate
  -> temporal/scene reasoning
       - suspected medication
       - visual-memory / forgotten-action logic
```

State clearly:
- action primitives are observations/candidates, not medical or physical certainty;
- low-level action extraction is scene-independent;
- medication interpretation occurs only in the scene/temporal layer;
- no project accuracy metric is claimed.
