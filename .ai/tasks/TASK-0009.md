## 1. Objective

Complete A4 by adding a scene-independent temporal visual-memory layer that can answer algorithm-level questions such as:

- "What did this tracked person/object do recently?"
- "What generic action facts were observed in this source/continuity segment?"
- "Where was this object last seen, and what recent interaction facts involved it?"

This must remain conservative memory over already-generated PrimitiveFacts. It must not invent a medical conclusion, definitive grasp/carry state, cross-camera identity, or missing/return event.

No frontend work belongs in this task.

## 3. Requirements

### 3.1 Add a generic temporal visual-memory module

Add a scene-independent module, for example `temporal_memory.py`, that consumes PrimitiveFacts and exposes recent action history while reusing the existing `VisualMemory` for object-location state.

A temporal action record must expose at least:
- fact_type;
- source_id;
- continuity_segment;
- timezone-aware UTC timestamp;
- confidence;
- subject identity + label when available;
- object identity + label when available;
- location/zone when available;
- explainable action geometry/provenance where present.

Do not store raw image/gray/RGB/BGR/pixel arrays.

### 3.2 Supported generic history facts

At minimum accept and preserve history for:
- `hand_near_object`
- `hand_to_face`
- `pickup_candidate`
- `putdown_candidate`
- `motion`
- `entered_zone`
- `left_zone`
- `object_in_zone`

`object_detected` may update the wrapped object-location memory but does not need to appear in the action-history list.

Do not reinterpret these facts into stronger claims.

### 3.3 Conservative identity and continuity boundaries

History queries must never merge identity by label alone.

Where identity exists, the effective scope must include:
- source_id;
- continuity_segment;
- subject/object track/entity ID.

Rules:
- same track ID on another source is separate;
- same track ID after a continuity gap is separate;
- same-label parallel objects remain separate;
- label filters may return multiple candidate histories but must not claim one physical identity;
- missing IDs may remain queryable as unbound facts, but must not be silently attached to tracked history.

### 3.4 Observation-gap semantics

`observation_gap` must create a hard sequence boundary.

Requirements:
- pre-gap and post-gap histories remain available as separate continuity segments;
- no temporal episode/query may imply continuous action across the gap;
- the object-location memory must preserve historical records without merging the post-gap track with the pre-gap track;
- a query that omits continuity may return multiple segment-scoped candidates, not one merged timeline.

### 3.5 Query API at the Python algorithm layer

Provide small deterministic query methods, for example:
- `recent_actions(...)`
- `last_action(...)`
- `timeline_for_identity(...)`
- `last_seen_objects(label=...)` delegating to `VisualMemory`

Exact naming may differ, but the API must support:
- filter by source;
- filter by continuity segment;
- filter by subject/object identity;
- filter by action fact type;
- optional label filter that returns candidates rather than merges;
- deterministic newest-first or chronological ordering documented and tested.

No REST/frontend endpoint is required in this task.

### 3.6 Bounded memory

Prevent unbounded in-memory growth.

Use a deterministic bounded policy such as:
- maximum action records, or
- maximum records per source/continuity identity.

Configuration must be validated and must not accept Boolean-as-integer mistakes.

Eviction must not mutate or corrupt the existing `VisualMemory` identity semantics.

### 3.7 Scene/reasoner compatibility

Do not move scene conclusions into memory.

Verify that:
- MedicationSequenceReasoner still consumes generic facts and still produces only reviewable `suspected_medication` when its sequence requirements are met.
- Workshop/object state reasoning remains independent and retains conservative removed/returned/missing semantics.
- The new memory can ingest the same fact stream without changing plugin outputs.

No plugin rewrite is required unless a narrow integration bug is discovered.

### 3.8 Deterministic end-to-end coverage

At minimum prove:

1. generic `hand_near_object` and `hand_to_face` facts appear in temporal history;
2. object location in zone A then zone B updates wrapped VisualMemory to B while history retains both temporal facts;
3. same-label parallel objects keep separate identity histories;
4. same track ID across sources never merges;
5. same track ID across an observation gap remains separate by continuity segment;
6. querying without continuity returns separate segment-scoped records/candidates rather than one merged episode;
7. label-only query returns candidates and does not assert one physical identity;
8. configured history bound evicts deterministically;
9. raw pixel/image metadata cannot enter memory records;
10. FrameFactExtractor output can be ingested directly;
11. medication reasoner/plugin regressions remain green;
12. workshop reasoner/plugin regressions remain green.
