## 1. Objective

Close the most important AI gap exposed by the current competition document:

The real Ultralytics path currently normalizes only person/pose detections, while the product algorithm depends on semantic non-person objects (medicine/tool/item) entering the same tracking -> relation -> action -> memory pipeline.

Implement a truthful real semantic-object detection path without fabricating a medication-specific trained model.

The target architecture is:

```text
RGB frame
  -> pose provider -> person + skeleton
  -> object detector -> semantic non-person objects
  -> combined detections
  -> existing tracker / relations / actions / memory
```

No frontend work belongs in this task.

## 2. Current State

- Real Ultralytics pose runtime is proven with yolo11n-pose.
- Canonical COCO17 skeleton contract exists.
- Current `UltralyticsProvider` intentionally filters to person classes only.
- Generic VisualMemory and action primitives already support arbitrary non-person labels once detections exist.
- Fixture JSONL can provide non-person objects, but that is not a real semantic object model.
- Current tracker/relation/memory layers are already label-generic.
- Baseline: 398 passed / VERIFY_OK.

## 3. Requirements

### 3.1 Separate pose and semantic-object responsibilities

Do not destroy the existing proven pose provider.

Add a semantic object detector adapter or generalize provider structure so that:
- pose path continues to emit person detections + keypoints;
- object path can emit non-person semantic detections from an Ultralytics-compatible detector result;
- arbitrary valid class labels are preserved rather than collapsed to person;
- invalid boxes/classes/confidences fail closed.

Medication/tool/custom labels must be supported by the adapter contract, but do not claim such a trained model exists unless a model is actually supplied.

### 3.2 Combined provider path

Provide a narrow composition mechanism so one frame may yield:
- person pose detections from the pose provider;
- semantic non-person object detections from the object detector.

Requirements:
- preserve source/timestamp through downstream normalization;
- avoid duplicate person detections when both component models expose person;
- deterministic ordering;
- one unavailable optional component must have an explicit truthful status;
- do not silently replace the pose path with motion_cpu when only the object component is unavailable.

Exact class/module naming is flexible, but the architecture must be explicit and testable.

### 3.3 Semantic object contract

For non-person detections preserve at least:
- label;
- confidence;
- bbox;
- provider/provider_version;
- class_id when available.

Do not attach fake skeleton/keypoints to non-person objects.

The downstream tracker must receive these labels unchanged so existing:
- person-object relations;
- `hand_near_object`;
- `object_in_zone`;
- VisualMemory
can work without scene-specific detector logic.

### 3.4 Config/runtime wiring

Add explicit environment/config wiring for the semantic object model path, separate from the pose model path.

For example:
- `AI_ULTRALYTICS_POSE_MODEL_PATH`
- `AI_ULTRALYTICS_OBJECT_MODEL_PATH`

Backward compatibility with existing `AI_ULTRALYTICS_MODEL_PATH` may be retained for pose if needed.

Provider status must truthfully expose:
- configured/unconfigured;
- dependency available/unavailable;
- model path;
- which component is selected.

Do not claim a custom medicine detector if none is configured.

### 3.5 Deterministic fake-result tests

Using injected fake Ultralytics-compatible results, prove:
1. person pose path still emits canonical skeleton detections;
2. object path emits arbitrary non-person labels such as `medicine bottle` and `tool box`;
3. same-label multiple object boxes remain separate;
4. person rows can be excluded from object-only mode to avoid duplicates;
5. malformed bbox/class/confidence fails closed;
6. object detections carry no fabricated keypoints;
7. combined provider returns person + non-person detections deterministically.

### 3.6 Pipeline integration

Add an integration test proving a semantic non-person detection can flow through the normal AI path into at least:
- tracked `object_detected`;
- one generic relation/action/location/memory-compatible fact where geometry/config supports it.

Prefer reusing `FrameFactExtractor` rather than building a test-only path.

No scene conclusion is required in this task.

### 3.7 Optional real-runtime smoke

If an already authorized lightweight official Ultralytics detection model/sample is available or can be obtained under the same prior runtime-smoke rules, run one ignored-path smoke through the new object adapter.

If performed:
- classify it only as REAL_RUNTIME_SMOKE;
- record model/sample provenance;
- do not call it medication recognition;
- do not report accuracy/benchmark claims;
- keep weights/media untracked.

If runtime assets are unavailable, do not block task completion; fake-result contract + integration is sufficient.

### 3.8 Tracking boundary

Do not replace the current tracker merely because the reference document mentions ByteTrack/Kalman.

Document:
- current Centroid/Hungarian path is the implemented tracker;
- ByteTrack/Kalman is a compatible future tracker alternative;
- no tracking-performance claim is made.
