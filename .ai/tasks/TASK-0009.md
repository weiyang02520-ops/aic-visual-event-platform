Add an Ultralytics-compatible semantic object adapter that can normalize arbitrary non-person classes.

Required normalized fields:
- label;
- confidence;
- bbox;
- class_id where available;
- provider/provider_version.

Requirements:
- labels such as medicine bottle, pill box, tool box, instrument etc. must survive unchanged;

- malformed/non-finite class/confidence/bbox fails closed;


- no duplicate person rows from the object detector;
- object-model unavailability must not silently disable the working pose path;
- statuses/configuration must tell the truth about which components are available.

# PACKAGE B — Temporal Visual Memory

## B1. Add scene-independent temporal memory

Create a generic module, e.g. `temporal_memory.py`, that consumes PrimitiveFacts and composes with existing `VisualMemory`.

It should retain/query recent evidence for at least:
- hand_near_object;
- hand_to_face;
- pickup_candidate;
- putdown_candidate;
- motion;
- entered_zone;
- left_zone;
- object_in_zone.

`object_detected` may update object-location memory without appearing in the action list.

## B2. Temporal record contract

Each record must preserve:
- fact_type;
- source_id;
- continuity_segment;
- timezone-aware UTC timestamp;
- confidence;
- subject identity/label if present;
- object identity/label if present;
- location/zone if present;
- safe explainable geometry/provenance.

No raw pixel/image arrays.

## B3. Identity and gap boundaries

History must never merge by label alone.

Effective tracked identity is scoped by:
- source_id;
- continuity_segment;
- track/entity ID.

Rules:
- same numeric track ID on another source is separate;
- same track ID after a gap is separate;
- same-label parallel objects remain separate;
- label-only query may return multiple candidates;
- missing IDs stay unbound rather than attaching themselves to tracked history;
- observation_gap is a hard temporal boundary.

## B4. Query API

Provide deterministic Python-layer query methods supporting:
- source filter;
- continuity filter;
- subject/object ID filter;
- label filter;
- fact/action type filter;
- recent actions;
- last action;
- timeline for identity;
- last seen object candidates via VisualMemory.

Document ordering (newest-first or chronological) and test it.

No REST/frontend endpoint in this task.

## B5. Bounded memory

Prevent unbounded growth.

Use a validated deterministic limit such as max records or max records per scoped identity.

Reject Boolean-as-integer configuration mistakes.

Eviction must not corrupt VisualMemory.

## B6. Integration evidence

Prove:
- FrameFactExtractor output can be ingested directly;
- zone A -> zone B leaves both temporal evidence and current last-known B state;
- same-label / cross-source / post-gap histories stay separate;
- no raw pixels survive;
- existing medication/workshop reasoners remain behavior-compatible.

# PACKAGE C — Schedule-Aware Medication Review

## C1. Add medication plan contract

Add a deterministic JSON-friendly plan schema.

A plan entry should support at least:
- plan/entry ID;
- medicine identity or normalized label;
- scheduled local clock time or explicit UTC timestamp;
- allowed early/late tolerance window;
- optional note/dose text carried only as user-configured metadata, not inferred from vision.

Strict validation:
- invalid/blank identifiers rejected;
- invalid timestamps/tolerance rejected;
- no Boolean-as-number coercion;
- timezone semantics explicit.

Do not require a database or frontend in this task.

## C2. Compare visual evidence with plan

Create a review-layer evaluator that combines:
- medication-associated temporal evidence;
- observed time;
- configured medication plan.

It may emit conservative review cues such as:
- plan_match_candidate;
- early_candidate;
- late_candidate;
- wrong_item_candidate;
- unresolved_candidate.

Do NOT emit:
- "dose was swallowed";
- "medical treatment was correct";
- dosage correctness inferred from vision;
- diagnosis/advice.

The result is evidence for review, not a medical conclusion.

## C3. Matching rules

At minimum:
- medicine identity/label must be compatible with the plan;
- source/time provenance preserved;
- no cross-source/gap evidence pairing;
- ambiguous same-label/multiple-object evidence remains unresolved or candidate-scoped;
- one observed event must not satisfy multiple plan entries silently unless deterministic policy explicitly allows it;
- repeated/debounced action evidence must not create duplicate fulfillment cues.

## C4. Deterministic tests

Prove:
1. correct item inside time window -> plan_match_candidate;
2. correct item too early -> early_candidate;
3. correct item too late -> late_candidate;
4. incompatible medicine -> wrong_item_candidate;
5. insufficient/ambiguous evidence -> unresolved_candidate;
6. same-label parallel objects do not collapse identity;
7. cross-source evidence does not fulfill a plan;
8. post-gap evidence does not combine with pre-gap episode;
9. repeat action within one debounced episode does not create duplicate plan fulfillment;
10. optional dose/note metadata is echoed only as configuration, never inferred.
