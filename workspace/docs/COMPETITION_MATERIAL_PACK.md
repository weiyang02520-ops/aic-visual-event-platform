## 1. 项目背景

传统摄像系统擅长录像，却难以把长时间视频直接转化为可解释、可复核的事件。单帧目标检测可以回答“画面里有什么”，但不能稳定回答“谁在什么时间、什么位置、对哪个对象做了什么”。本项目在既有 livestream-rs 与 Makerverse 直播系统上增加独立视觉事件 AI 中间件和前端控制台，将视频、视觉事实、场景规则、证据时间窗和人工复核组织成可扩展系统。

## 2. 主要痛点

- 直播、AI 识别、场景规则和机器人执行往往相互耦合，难以替换和复用；
- 家庭/工作室存在大量长尾物品，重新训练全量检测器成本高；
- 长视频事件需要时间窗和历史证据，单帧结果不易复核；
- 模型置信度不能直接等同于事实，必须提供人工确认和降级状态；
- 最终机器人应用需要把感知与动作执行解耦，并受硬件和安全资料约束。

## 3. 总体架构

```text
livestream-rs / Makerverse
          ↓ live endpoint
VideoSourceAdapter → Frame/Detector/Tracker → PrimitiveFact
          ↓                                      ↓
EvidenceResolver ← UnifiedEvent ← Scene Plugins
          ↓              ↓
       SQLite/REST ← React 前端控制台
                                      ↓
                              未来 Robot Adapter
```

直播系统保留自己的职责；AI 服务以中间件方式消费帧或媒体端点；前端通过统一 Repository 同时支持 Mock 和 Real；机器人只在资料和实机验收后接入。

## 4. AI 算法

算法链路由来源、抽帧、检测、跟踪、关系事实、插件和证据组成。当前采用 CPU motion baseline、fixture 和可替换 provider，确保在没有 GPU/FFmpeg 时仍可运行 schema 与 API 测试。ONNX provider 没有经过输入/输出 adapter 验证时保持 unavailable，避免误报。

注册对象/人员使用参考特征和余弦相似度建立软件契约，属于 heuristic baseline，不是人脸识别准确率。真实模型、数据集和指标待补。

## 5. 插件化创新

插件由 manifest 自动发现，支持动态导入、全局启停、并行评估和异常隔离。养老插件输出“疑似服药”等事件；工作室插件输出物品进入/离开/缺失等事件。新增场景只依赖统一 PrimitiveFact，不复制底层视频与数据库逻辑。

## 6. 智慧养老应用

当系统观察到人物、药盒和相关时序关系时，养老插件生成带时间窗的疑似事件。家属或照护人员可在事件中心查看事实、来源、证据状态并确认/驳回。系统不作医疗诊断，不把启发式事件写成真实服药证明。

## 7. 工作室应用

工作室插件复用人物、物品、区域和时间事实，用于工具/物料进入、离开、缺失和工作区状态变化。该场景证明通用视觉底座可以迁移到养老之外，并为机器人巡检和寻物提供事件接口。

## 8. 视频证据复核

每个事件保留 source_id、开始/结束时间和 resolver 状态。fixture、已提供但未验证、可回放和不可用状态严格区分。真实部署后，可将 live_id、playlist、segment 与 AI 时间戳映射，再由前端提供受控回放入口。

## 9. 前端系统

控制台包括 Dashboard、Monitor、Events、Event Detail、Plugins、Registry 和 Settings。Mock 模式用于演示；Real 模式连接 AI API，并可选连接 Makerverse。事件支持搜索、状态筛选、详情查看和人工复核。媒体类型和错误状态显式呈现，不生成虚假直播地址。

## 10. 机器人融合位置

机器人作为感知载体和移动执行终端，可在后续实现“发现事件→定位/带路/寻物/建议动作”的闭环。具体机器人型号、相机、通信协议、动作能力、供电和安全限制必须依据老师资料与实机证据确定；当前仅保留 adapter 位置和验证清单。

## 11. 创新点

1. 通用视觉事实层与场景插件层分离；
2. 自动发现、并行、可启停和异常隔离的插件机制；
3. 面向长尾物品的低门槛注册接口；
4. 从单帧检测升级为带关系和时间窗的视觉事件；
5. AI 判断、历史证据和人工复核协同；
6. 软件底座与机器人执行解耦，支持多场景迁移。

这些是系统级设计创新，不等于已完成真实指标。量化结论见 `EXPERIMENT_PLAN.md` 的待填表。

## 12. 实验与验收

最终实验应报告检测、跟踪、事件、时间窗、延迟、稳定性和注册匹配指标，并包含真实视频、故障注入、浏览器、直播和机器人验收证据。当前全量 AI 回归为 414 passed，仅完成 Mock、JSONL、短 AVI、本地 API 和前端 build/smoke 验证；这些属于 `MOCK_OR_LOCAL`，不能替代规则要求的真实效果验证。

## 13. 风险与未来工作

主要风险包括缺少真实部署工具链、模型/数据不确定、媒体时间轴不一致、误报漏报、人员隐私、机器人动作安全和多实例一致性。后续按 P0 资料真实性、P1 媒体模型、P2 机器人闭环、P3 工程化顺序推进。
