# 实验设计与待填数据表

## 1. 实验原则

实验必须在老师赛道、机器人型号、数据授权和评价规则明确后锁定。当前文档提供可执行协议和空表，不填入虚构指标。所有结果需记录代码版本、配置、数据划分、设备、随机种子和原始日志。

## 2. 数据划分

建议按场景、摄像头和时间段划分 train/validation/test，避免同一视频相邻帧泄漏到不同集合。养老场景至少覆盖无人、单人、多人、遮挡、光照变化、药盒相似物和未服药等负例；工作室场景覆盖工具替换、物品离开、多人交叉和区域边界。

## 3. 指标表（待填）

| 层级 | 指标 | 数据/脚本 | 当前值 | 证据要求 |
|---|---|---|---|---|
| 检测 | precision / recall / mAP | 真实标注集 | 待测 | 固定类别和 IoU |
| 跟踪 | IDF1 / HOTA / ID switches | 连续视频 | 待测 | 明确遮挡规则 |
| 事件 | precision / recall / F1 | 事件标注 | 待测 | 事件级而非帧级 |
| 时间 | 起止时间误差 | 时间窗标注 | 待测 | 统一时区/时间基 |
| 系统 | 端到端延迟、吞吐 | 部署环境 | 待测 | CPU/GPU/分辨率 |
| 稳定性 | 断流恢复、停止响应 | 故障注入 | 待测 | 日志和任务状态 |
| 注册 | top-k 命中率、拒识率 | 参考图集 | 待测 | 隐私和阈值记录 |

## 4. 对照与消融

建议比较：单帧规则 vs 时序事件、无关系层 vs 有关系层、固定模型类别 vs 注册对象、无证据 resolver vs 有证据 resolver、单插件 vs 多插件。每个消融只改变一个机制，并记录显著性或置信区间（若样本量允许）。

## 5. 场景验收

- 养老：疑似服药事件必须可追溯到人物/药盒/时间窗，并允许人工确认/驳回；不产生医疗诊断。
- 工作室：物品进入、离开或缺失事件必须带区域和对象信息；相似物和未知物进入 unknown。
- 机器人：仅在协议、相机和安全规则核验后测试“感知→事件→建议动作”，动作执行另设硬件安全闸门。

## 6. 当前已验证的替代实验

仓库已用 Mock、JSONL 和短 AVI fixture 验证帧到事件的结构链路、任务停止、插件状态和接口返回。它们证明软件契约，不可替代真实数据集的准确率或机器人现场结果。

## 7. AIC AI+场景创新对齐

官方规则将 AI+场景创新拆为创新性（20）、需求分析（15）、解决方案可行性（20）、项目实施（15）、测试与验证（10）、应用效果（15）和总结与展望（5）。实验包应为每项评分准备独立证据，不能把 344 个本地回归测试直接当成应用效果或真实识别指标。

新增的隐私实验闸门：

1. **源头处理**：记录相机/边缘节点是否在原始帧离开采集设备前完成骨骼化或脱敏；当前项目没有该真实模块，状态保持“待验证”。
2. **最小化输出**：帧预览 API 已递归对常见图像、深度和像素字段做编码/尺寸摘要化，并有顶层与嵌套回归测试；仍需在真实相机/边缘链路上验证原始图像是否被写入事件库、日志、证据 resolver 或提交包。
3. **身份弱依赖**：分别评估有可靠人物关联、无人物 ID 但有区域/对象/时间证据、多人/遮挡三类输入；缺少身份时只允许不完整线索或人工复核，不把步态/骨骼形态写成已实现身份认证。
4. **展示脱敏**：卡通化/骨骼化展示单独记录为 UI 演示证据，不能替代相机源头隐私处理证据。

场景实验应覆盖“忘记物品位置”和“忘记之前操作”两个问题族，并在养老药品、工作室工具/物料之间做迁移测试。实际应用效果、用户反馈、隐私合规和机器人现场数据均需授权来源；在资料到位前只保留 `MOCK_OR_LOCAL` 结果。
