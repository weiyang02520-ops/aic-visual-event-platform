## 2. AI 服务已经具备的能力

当前服务的主链路为：来源检查 → 帧抽样 → 检测/跟踪 → 关系事实 → 场景插件 → 统一事件 → 证据时间窗 → SQLite 持久化 → REST 查询。服务包含健康检查、插件扫描与全局启停、Mock/JSONL/OpenCV 帧输入、CPU motion baseline、可替换 detector provider、事件复核、分析任务状态、停止语义、对象/人员登记和注册特征匹配。

注册特征当前是可解释的 CPU heuristic：灰度图 4×4 网格均值与 16-bin 强度直方图组成归一化向量，再使用余弦相似度匹配。它不是人脸识别、身份认证或训练模型准确率，最终材料必须把它标记为基线能力，不能填写未测得的 precision、recall 或 FPS。

模型 provider registry 对 ONNX 做了保守边界：即使运行时和权重文件存在，只要没有经过验证的输入/输出 adapter，就保持 unavailable 并选择 motion_cpu。这样可以避免“文件存在”被误报成“模型可用”。

## 3. 前端已经具备的能力

前端包含 Dashboard、Monitor、Events、Event Detail、Plugins、Registry 和 Settings 视图，支持 Mock/Real 模式切换、事件关键词搜索、复核状态筛选、事件详情抽屉、事实与证据时间窗展示、确认/驳回、分析任务轮询，以及可选 Makerverse 在线直播 adapter。

Makerverse adapter 能归一化 PascalCase/lowerCamelCase DTO，并根据 URL 分类 HLS、HTTP-FLV、RTMP、RTSP 和未知类型。未配置真实地址、在线直播为空、请求失败或 resolver 没有可验证 URI 时，界面明确显示待接入/待解析，而不是生成一个假的播放地址。

## 4. 当前已执行的验证

### 4.1 AI 单元和接口测试

在 `workspace/ai-engine` 运行：

```powershell
$env:PYTHONDONTWRITEBYTECODE = "1"
python -B -m pytest --basetemp=.codex-pytest-temp-overview -p no:cacheprovider -q
```

核验结果：`414 passed`。新增回归确认 JSONL 恢复坏行会发出 observation_gap、重开 detector session、清除 tracker/关系/关键点连续状态，并阻止服药与工作室推理跨连续段关联；此前回归确认检测缺口会清除上一位置、人物—物体接近和区域成员状态，跨漏检帧不推断 `motion`、`putdown_candidate` 或 `left_zone`，且清除对应关系/运动/区域 cooldown；非有限的成对距离与位移不会生成关系或 motion 事实；布尔关键点不会生成 `hand_to_face`；无法安全转换为有限浮点的极大关键点坐标也按缺失证据处理；帧管线拒绝布尔/小数/字符串/负值抽帧参数并拒绝超范围 timedelta；OpenCV 非有限 FPS/PTS 使用有界 fallback，时间仍不可表示时显式失败；帧差 detector 保留浮点灰度并拒绝无效像素；并发分析使用独立帧差状态；抽样帧差检测框映射回原帧像素坐标；运行中的帧提取通过每 job 取消令牌在帧边界停止；停止与完成在终结锁下串行化，事件批次和 completed 状态在同一 SQLite 事务提交，完成任务重跑不重复落库；溢出成无限右/下边界的框和区域会被拒绝；注册特征拒绝布尔/数字字符串与无效范围；药品 ID 缺失时按标签区分候选；药柜/药架/药房等储存标签以及药品说明书、用药记录、药品清单、处方单等文档标签不作为药品目标；显式非人物主体、无效身份 ID 和布尔/字符串置信度不会进入服药推理。低分早期手部事实不掩盖后续达阈值动作，低分可选放下事实不会拉低完整候选。新证据来自 JSONL/CPU fixture 与本地 API，不代表真实身份识别、遮挡或姿态模型实测。时序、关系、运动检测和跟踪阈值拒绝布尔值/字符串及非有限数值；超大整数无法转为有限 float 或超出 timedelta 范围时统一产生 ValueError，推理入口也会复核可变 PrimitiveFact 的 confidence。工作室事件去重保留 zone_id/区域名，不会把同一对象同一时刻不同区域的状态变化合并。关系冷却键使用结构化实体/区域字段，ID 中的冒号不会造成键碰撞。JSONL 显式 objects 列表含坏记录时任务失败并不落库；缺少 objects 字段仍视为空帧。API 回归确认非法 fixture 置信度会使分析任务失败且不落库事件；浮点框阈值测试保持 50.8 px 精度。跟踪器对人物别名使用共享分类器，避免标签大小写或已支持别名变化造成不必要的 track ID 断裂。FixtureDetector 保留浮点框精度，并拒绝非法置信度，防止阈值附近距离被截断或 NaN 被裁剪成高分。Entity 与 Zone 直接构造均有严格输入校验，重复实体/区域 ID 会在关系状态更新前失败。直接构造区域与 JSON 环境配置共享 ID/标签/坐标校验，重复区域 ID 会在关系状态更新前失败。显式缺失事实若带区域标注，只配对同一区域的待处理移出状态。超时缺失的移出与观察事实若都带区域标注，必须属于同一区域。工作室时序状态现按对象与区域分别记录待归还事实，跨区移动不会覆盖原区状态；相同时间戳的移出与进入/缺失不会按输入顺序配对推断先后。服务可通过 `AI_ZONES_JSON` 加载可选帧像素矩形，默认区域为空；当前尚无现场校准坐标。Python 3.14 下出现来自 FastAPI/Starlette 的 `asyncio.iscoroutinefunction` 弃用警告，但未影响测试结果；这些测试验证本地规则、CPU baseline、Mock/fixture 和接口契约，不代表真实数据集指标。

## 5. 证据等级和禁止误读

| 标签 | 含义 | 可以写入最终文档的表述 |
|---|---|---|
| `STATIC_VERIFIED` | 阅读源码、接口和配置得到的事实 | “源码中定义了……” |
| `MOCK_VERIFIED` | 确定性 fixture/Mock 测试 | “在 Mock 条件下验证……” |
| `LOCAL_SERVICE_VERIFIED` | 本机启动 AI 服务后的 HTTP 或链路验证 | “本地服务联调通过……” |
| `REAL_DEPLOYMENT_VERIFIED` | 真实 Makerverse/livestream-rs 部署与网络证据 | 当前尚未取得 |
| `ROBOT_HARDWARE_VERIFIED` | 真实机器人、相机、通信和安全验收 | 当前尚未取得 |

当前结果只能使用前三种标签。不能把 Mock 事件写成摄像头准确率，不能把 endpoint DTO 适配写成真实 HLS 播放成功，不能把机器人占位卡写成机器人控制已接入。
