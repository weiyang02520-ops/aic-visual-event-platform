# 局限与后续工作

## 当前局限

1. detector/tracker 是 CPU baseline、fixture 和可替换协议，不代表真实目标检测精度。
2. 注册 embedding 是启发式向量，不是人脸识别、身份认证或安全决策。
3. 没有授权训练/测试集，未报告 precision、recall、F1、FPS 或延迟指标。
4. FFmpeg、Cargo、.NET SDK 缺失，真实 livestream-rs/Makerverse 运行链未验收。
5. 真实 HLS/HTTP-FLV 播放、CORS、鉴权、直播时间轴和证据回放尚未验证。
6. 机器人型号、通信协议、相机、部署系统和安全规则尚未获得，机器人 adapter 仅占位。
7. 前端 build 和 HTTP smoke 已通过，但浏览器点击、响应式截图和现场演示尚未做最终验收。
8. 当前 SQLite、内存任务和本地运行方式不适合未经设计的多实例生产环境。

## 后续优先级

### P0：资料和真实性

接收老师主文档与机器人资料，登记来源，锁定赛道、评分点、硬件和安全边界；安装或提供真实工具链与部署地址。

### P1：媒体与模型

补齐真实 source adapter、断流重连、HLS/HTTP-FLV 播放、时间轴映射和模型 input/output adapter；建立授权数据集、标注、训练和评估脚本。

### P2：应用闭环

在机器人安全规则允许的范围内实现建议动作/寻物/带路等 adapter，只在实机日志、照片和回滚方案齐全后宣称硬件验收。

### P3：工程化

加入身份鉴权、审计日志、密钥管理、队列、多实例存储、监控、限流、隐私删除和自动化 CI。

## 伦理与隐私

老人、人员图像和 embedding 需要最小化采集、授权、访问控制和可删除机制。系统输出“疑似事件”和证据入口，不替代医疗、安防或人工决定。最终比赛材料应单列误报、漏报、拒识和人工复核策略。
