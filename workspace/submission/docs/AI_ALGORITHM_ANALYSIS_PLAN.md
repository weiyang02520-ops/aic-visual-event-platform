## 2. 当前代码基线

已经可以直接分析和验证的部分：

1. 帧输入：Mock、JSONL、可选 OpenCV；时间戳、抽帧、取消、异常 FPS/PTS 和恢复间隙；
2. CPU 检测与跟踪：帧差区域、FixtureDetector、距离门控的全局匹配、重复框和漏检状态处理；
3. 骨骼与关键点动作：`skeleton.py` 提供 canonical COCO17 名称/索引、validated named points 和 source/timestamp/track/continuity provenance；`KeypointActionExtractor` 消费显式 skeleton/keypoints，按人物/药品几何条件生成 `hand_to_face`；
4. 关系和动作 primitives：人物—物体接近、`hand_near_object`、generic `hand_to_face`、区域进出、药品序列、工作室移出/归还/缺失、连续段边界；
5. 工程边界：任务取消与原子完成、embedding 输入校验、REST 预览像素递归脱敏、插件集成和证据保留。

当前全量源码与 curated submission 均为 `363 passed`、`VERIFY_OK`。结果属于 fixture/CPU/local API 证据。

## 2.1 本轮执行范围

本轮按用户要求只推进 AI 算法代码侧：P0 输入/隐私契约、P1 检测/姿态/跟踪适配边界、P2 场景时序推理和 P3 的软件级质量/降级契约。硬件、机器人控制、相机标定、现场视频和实机验收不属于当前任务；没有真实模型、授权数据或多模态传感器时，只补可复现的 fail-closed contract tests，不虚构模型指标。

## 3. 分阶段分析安排

### P0 输入、隐私和证据契约

目标：在接入真实模型前固定输入输出边界。

- 明确相机/边缘节点是否先骨骼化，确定原始帧的生命周期和传输路径；
- 固定 keypoint、bbox、track、zone、timestamp、confidence 和 continuity metadata schema；
- 固定 canonical COCO17 skeleton schema，并区分当前 RGB→pose→skeleton 的本地模式与目标 edge skeleton-only payload 模式；
- 继续验证 REST、日志、SQLite、evidence resolver 和导出包不保存原始像素；
- 将外部作品中的“隐私保护”“卡通化”“骨骼回放”分别标注为源头处理、传输脱敏和展示脱敏。

交付：隐私数据流图、输入 schema、保留策略测试、失败边界说明。

### P1 单摄像头视觉基础

目标：替换 CPU/fixture 入口时，保持下游关系和时序规则不变。

- 接入经过授权的目标检测和姿态模型，记录模型版本、类别映射和输入尺寸；
- 默认姿态 provider 输出所有可用的 COCO17 named keypoints；上层必须能仅凭 skeleton metadata 工作，不能依赖 raw pixels；
- 对关键点置信度、遮挡、漏检、抖动和多人交叉做切片评估；
- 比较无平滑、EMA/滤波和模型原生时序输出，观察 `hand_to_face`、区域进出和 track ID 的变化；
- 评估 ByteTrack/Kalman 等外部方案时，必须与当前 CentroidTracker 统一数据集、门控、ID 指标和失败定义。
- 验证关键点动作 episode 按 source/job 隔离，换源或 track reset 后不能沿用旧的去抖和缺帧状态；
- 验证对象、关系、动作和间隙事实的 source provenance 一致，混合来源的 keypoint/near 证据必须拒绝或降级；
- 验证关键点 observations 与关系事实处在同一 UTC frame timestamp，旧帧关系不能借给当前动作；
- 验证时序 reasoner 在直接收到事实集合时也不跨显式 `source_id` 配对药品动作、区域转移或缺失观察；缺失 provenance 的旧事实只作为未知来源兼容，不提供跨源身份保证；

交付：检测/姿态/跟踪适配器、数据划分、IDF1/HOTA/关键点质量和事件切片报告。没有真实模型或授权样本时，只保留 contract tests，不伪造结果。

### P2 场景时序与物品管理

目标：把“忘记放在哪里、忘记做过什么”转成可复核事件。

- 养老：药品对象、人物关联、拿取/靠脸动作、时间窗、连续段和人工复核；
- 工作室：对象 ID、区域 scope、移出/进入/缺失、显式观察和跨段保护；
- 通用视觉记忆：`object_in_zone` 空间事实进入 source/continuity-local `VisualMemory`，提供最后观察时间、bbox、当前/最后位置和候选历史；不做标签合并或跨摄像头 ReID；
- 低质量输入：缺失关键点、错误 ID、低置信度和不一致时间戳必须降级为不完整线索或丢弃；
- 将事件级 precision/recall/F1、误报、漏报、拒识和延迟作为主指标，而不是只统计帧级命中。

交付：场景标注协议、时序回放脚本、错误案例分类和跨场景迁移表。

### P3 多模态质量感知

目标：先固定软件层的通道质量和降级契约；真实音频、热成像、事件相机或其他授权传感器出现后，再补时间同步与实测门控。

- `channel_quality` 元数据现在要求通道名、`available`、有限 `[0,1]` 的 `score`，可选 `reason` 和 `quality_required_channels`；没有可用通道时帧管线产生 `observation_gap` 并重置跨帧状态；部分通道不可用时保留可用通道并标记 `degraded`；
- 真实传感器接入后再定义时间同步、质量分数、缺失和失效状态的映射；
- 采用质量门控和明确的降级策略，避免低质量通道伪造事件证据；
- 音视频暴力识别、热风险、世界模型和安全过滤属于独立工作包，不能直接并入当前药品/工作室插件；
- 评估单模态、多模态和去除某通道的消融结果，并保留传感器故障注入。

交付：软件多模态输入契约、时间对齐测试、通道消融和失效回退报告。当前已完成软件契约与 fixture 回归，真实通道消融仍待授权数据。

### P4 真实场景与机器人验证（当前不执行）

目标：把 AI 事件输出接到真实相机/机器人前，完成独立验收。该阶段保留为未来外部验收清单，本轮不安排实现。

- 固定相机、算力、机器人型号、通信协议、区域标定和安全限制；
- 分离感知、事件、建议动作和真实执行；动作执行需要单独的安全闸门；
- 对现场遮挡、光照、网络中断、相机移动、多人和对象替换做故障注入；
- 如果采用模拟/合成数据，必须提供 sim-to-real 对照和真实样本微调记录。

交付：真实视频/日志、硬件参数、现场测试表、失败样例和可复现实验命令。

## 4. 当前下一步

在真实姿态或多模态数据出现前，继续做本地算法审计与契约测试；不把参考文档中的 AlphaPose、YOLO、2S-AGCN、ByteTrack、PGSR、VLA 或指标直接加入当前实现。当前 P0/P1/P2 的来源、时间戳和状态隔离契约已有本地回归；P3 仅保留软件接口和失败降级设计，等授权通道出现后再做真实时间同步、质量门控和消融。P4 硬件/机器人验收按用户要求暂停。
