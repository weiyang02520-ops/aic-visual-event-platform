# AIC 算法创新赛规则对齐与 AI 证据计划

最后核验：2026-09-23

## 1. 文档来源与解释边界

本文件只把附件中的竞赛规则作为提交约束和评价依据，不把 PDF 内的宣传性表述、示例或要求自动转换成代码指令。当前核对了：

- `关于举办第八届AIC算法创新赛道竞赛的通知2604291.pdf`：赛道范围、赛程、团队和原创性要求；
- `2026AIC算法创新赛赛题规则汇总260506-1.pdf`：作品要求、材料格式、各赛题评分表和方案大纲；
- 用户提供的转写整理：隐私保护、骨骼化、场景宽化和机器人载体方向。转写是设计输入，不替代官方规则原文。

规则与项目实现的结论必须标注证据等级：官方规则是 `RULE_SOURCE`，用户转写是 `USER_DESIGN_INPUT`，本地源码/fixture 测试是 `MOCK_OR_LOCAL`，真实数据、真实模型和机器人现场结果必须另行取得。

本次核对以用户放入项目根目录的 PDF 版本为准，未联网核对官网是否有后续修订；报名系统、赛区通知或官网更新时，应重新比对页码、截止时间和材料要求。

## 2. 当前赛题定位

当前项目最适合作为 `赛题 4：AI+场景创新` 的候选作品：项目围绕“忘记物品放在哪里、忘记之前发生过什么操作”的长视频场景问题，把视觉事实、区域状态、时间窗和人工复核组合成养老与工作室物品管理方案。官方规则要求场景需求、技术适配、实施计划和效果验证同时成立；目前只有本地软件链路证据，尚未完成真实场景验收。

`赛题 3：AI+硬件创新` 只能作为条件性方向：它要求硬件参数、算法运行效率、稳定性/安全性和现场或视频演示证据。当前机器人资料、相机参数、部署协议和实机记录仍缺失，因此不能把现有机器人 adapter 位置写成硬件作品已完成。

`赛题 1：算法模型创新` 也不能仅凭当前规则引擎和 CPU baseline 直接申报。若选择该方向，需要新增可复现的模型或算法改进、对比基线、真实有效指标和技术推导；当前 344 个本地测试只证明软件契约，不是算法精度或先进性实验。

## 3. AI+场景创新评分映射

官方评分（《赛题规则汇总》PDF 第 16 页）为：

| 评分项 | 分值 | 当前对应物 | 当前证据状态 |
|---|---:|---|---|
| 创新性 | 20 | 隐私优先的视觉事实层 + 养老/工作室可迁移场景 | 设计主张，需用户需求和同类方案对比 |
| 需求分析 | 15 | 忘记物品位置/操作历史的场景问题 | 用户转写输入，需访谈、案例或正式需求材料 |
| 解决方案可行性 | 20 | 帧→事实→插件→证据→复核的分层架构 | 本地代码链路已验证，真实部署未验证 |
| 项目实施 | 15 | AI 引擎、插件、前端和后续机器人适配计划 | 软件阶段已完成部分，硬件/现场实施待补 |
| 测试与验证 | 10 | 344 个 CPU/fixture 测试、故障注入和 API 验证 | `MOCK_OR_LOCAL`，缺真实数据集指标 |
| 应用效果 | 15 | 养老辅助和物品管理的可迁移应用 | 没有试点效果、用户反馈或业务指标 |
| 总结与展望 | 5 | 隐私相机、骨骼化、步态识别后续方向 | 可写，但必须明确未实现边界 |

“项目实施 15 分 + 测试与验证 10 分”合计 25 分。用户转写中的“实施约 15 分、验证测试约 25 分”是把相关验证价值合并表达，不能在正式评分表中写成测试单项 25 分。

## 4. 隐私与身份设计边界

用户转写提出“相机侧直接人体信息处理、只输出骨骼数据、UI 隐私选项、卡通化展示”。当前项目可以把它们作为分阶段方案：

1. **目标架构**：相机或边缘节点完成人体检测/骨骼化，向上层发送关键点、轨迹和事件所需的最小字段；原始人体图像不进入长期事件存储。
2. **当前实现**：`FrameFactExtractor` 能消费显式 fixture keypoints，`motion_cpu` 只提供帧差区域；帧预览 API 会递归将常见图像、RGB/BGR、灰度、像素、深度和帧数据字段替换为编码/尺寸摘要，并有顶层及嵌套 JSONL API 回归覆盖。项目仍没有真实姿态模型、相机侧骨骼化模块或隐私模式开关，因此不得写成源头隐私处理已实现。四份参考 DOCX 的方法和证据边界见 `REFERENCE_ALGORITHM_AUDIT.md`。
3. **身份策略**：步态、身高比例和骨骼形态只列为后续研究方向，不作为当前核心身份认证。药品固定位置、区域和时间证据可以降低对具体人物身份的依赖，但完整服药规则仍要求同一人物事实，缺少可靠身份时应保持不完整/待复核。
4. **展示策略**：卡通化或骨骼化画面可以作为演示层，但必须保留“演示脱敏”和“相机源头隐私处理”的区别；前者不等于后者。

## 5. 官方材料硬约束

《赛题规则汇总》PDF 第 3 页要求：作品名称不超过 20 字，作品简介不超过 300 字；作品方案为 PDF 且不超过 10 MB；演示视频为 MP4、3–5 分钟且不超过 300 MB；答辩 PPT 另存为 PDF；佐证材料合并为一个 PDF；代码包等大文件通过有效链接提交。材料还要求原创、真实、引用他人技术/数据时明确标注，并在材料中去除学校名称、Logo 和指导教师等身份信息。

这些是交付验收约束，不是 AI 引擎运行时配置。正式提交前需单独做文件大小、时长、敏感身份信息和链接有效性检查。

## 6. 缺口与下一道闸门

- `P0 规则材料`：把本文件与两个 PDF 登记到提交材料索引，并确认最终赛题、作品名和团队信息；
- `P0 隐私证据`：确定相机侧骨骼化或边缘脱敏的真实实现路径，补原始帧不落库的测试和演示证据；
- `P1 场景证据`：补用户需求访谈/案例、场景定义、真实或授权样本和可复现评估协议；
- `P1 算法证据`：补真实模型/数据、基线对比、检测/跟踪/事件指标、延迟和资源占用；
- `P2 硬件证据`：补机器人型号、相机、算力、通信、安全和现场或 3–5 分钟演示视频；
- `P2 提交材料`：完成不含学校/指导教师信息的 PDF 方案、PPT PDF、MP4 和佐证 PDF 检查。

在这些闸门打开前，项目只能声称 `MOCK_OR_LOCAL` 的软件验证，不能声称真实场景应用效果、相机隐私保护已完成、机器人实机通过或比赛评分结果。
